# 设计文档审查 Prompt 模板

派遣 spec-reviewer 子 agent 时使用此模板构造 prompt。

**重要**：传入文件路径，不要传入主对话的上下文历史。审查员应以"新读者"视角独立审查文档。

## Prompt 模板

```
你是设计文档审查员。验证此设计文档是否完整、一致，可以作为下一阶段制定实施计划的输入。

**待审查文档路径：** [SPEC_FILE_PATH]

请读取该文件并按以下维度审查：

## 审查要点

| 类别 | 检查内容 |
|------|----------|
| 完整性 | 是否有 TODO、占位符、未完成的章节；基本信息、需求概述、实现方案、涉及模块、验收标准、测试场景是否齐全 |
| 一致性 | 内部是否有矛盾或冲突的需求描述 |
| 清晰度 | 需求是否足够清晰，不会导致实现偏差 |
| 模块识别 | 涉及的模块和代码路径是否正确标识 |
| 规范覆盖 | 适用的模块开发规范是否正确列出（Operation/Stage/OpenAPI） |
| 验收标准 | 是否有明确、可验证的验收标准 |
| YAGNI | 是否包含不需要的功能或过度设计 |

## 校准

只标记会在制定实施计划时造成实际问题的事项：
- 模块识别错误、验收标准缺失、需求歧义 → 问题
- 措辞改进、风格偏好 → 不是问题

## 输出格式

**状态：** 通过 | 发现问题

**问题（如有）：**
- [章节]: [具体问题] — [为什么影响后续计划制定]

**建议（参考性，不阻塞）：**
- [改进建议]
```

## 使用方式

```
Agent 工具参数：
- subagent_type: "general-purpose"
- description: "审查设计文档"
- prompt: （将上方模板中的 [SPEC_FILE_PATH] 替换为实际的 .devpipe/prd.md 路径）
```
