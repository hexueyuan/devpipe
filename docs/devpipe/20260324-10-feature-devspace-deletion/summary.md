## 原始需求

开发完成后需要清理不再使用的开发空间（worktree、Docker 容器、数据卷等），手动清理容易遗漏资源，导致磁盘空间浪费。需要安全的清理向导。

## 需求分析过程

清理流程需要格外小心，防止误删有用数据。设计 3 步向导：环境探测（列出所有关联资源）→ 变更警告（检查未提交/未推送的代码）→ 执行清理。清理顺序很重要：必须先停容器再删 volume，最后删 worktree 和分支，避免依赖关系冲突。

## 实现方案

复用 `devspace_service.py` 的资源探测能力，新增清理执行逻辑。探测阶段检查 Docker 容器状态、数据卷、git worktree、本地和远程分支。清理按固定顺序执行：stop container → remove container → remove volume → remove worktree → delete branch。向导 UI 清晰展示每一步的风险提示，未提交变更时要求二次确认。

## 问题与解决方案

### 问题 1：清理顺序依赖问题

Docker 容器运行时不能删除挂载的 volume，worktree 被容器使用时也不能直接删除。通过固定清理顺序（容器 → 卷 → worktree → 分支）解决依赖问题。

## 反思与复盘

安全是清理功能的第一优先级。3 步向导给了用户充分的知情权，变更检查避免了误删代码。与创建功能的代码复用度较高，devspace_service.py 的抽象层次验证了设计的合理性。
