## 原始需求

用户报告创建开发空间时，如果之前创建过同名空间（即使已删除），创建流程会卡住不动，无法完成也无法取消。

## 需求分析过程

排查发现 `devspace_service.py` 的创建流程中，`init-env.sh` 脚本在资源已存在时（如 worktree 目录、Docker 容器、数据卷、分支）会阻塞等待用户输入，但在 Web 创建场景下没有交互式输入通道，导致永久卡住。根因是冲突检测不完整，只检查了部分资源。

## 实现方案

在创建前增加全面的资源冲突预检机制：检查 git worktree 是否已存在、Docker 容器是否在运行、数据卷是否存在、分支是否已创建。发现冲突时自动清理残留资源（停止容器、删除数据卷、移除 worktree），确保创建流程不会被阻塞。

## 问题与解决方案

### 问题 1：init-env.sh 在资源已存在时阻塞

原脚本使用交互式 prompt 询问是否覆盖，在非交互模式下导致阻塞。解决方案是在调用 init-env.sh 之前完成所有冲突检测和清理工作，确保脚本执行时不会遇到已存在的资源。

## 反思与复盘

这是一个典型的"交互模式假设"导致的 bug。Web 场景下的自动化流程不能依赖交互式输入。修复时采用"预检 + 自动清理"策略，比修改 init-env.sh 脚本更安全，避免影响命令行场景。
