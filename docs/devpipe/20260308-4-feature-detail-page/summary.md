## 原始需求

列表页提供了概览视图，但开发者需要查看单个分支的完整开发上下文。需要详情页展示子任务列表、验收标准、完整的开发元数据等信息。

## 需求分析过程

详情页需要聚合多个数据源：context.json（元数据）、task-progress.md（子任务）、prd.md/coding-plan.md（验收标准）。确定使用正则匹配从 Markdown 表格中提取子任务信息。路由设计为 `/detail/<name>`，name 使用 worktree 分支名。

## 实现方案

新增 Flask 路由 `/detail/<name>`，聚合 worktree 的所有开发上下文数据。`parse_subtasks()` 使用正则从 task-progress.md 中提取子任务表格。`parse_acceptance_criteria()` 从验收标准章节提取列表项。详情页模板分为基本信息区、子任务网格、验收标准列表三个区域。

## 问题与解决方案

### 问题 1：子任务表格正则匹配

task-progress.md 中的表格格式可能有空格差异，正则模式 `\|\s*(\d+)\s*\|\s*([^|]+)\s*\|\s*([^|]+)\s*\|\s*(已完成|当前|待执行)\s*\|` 通过 `\s*` 兼容不同对齐方式。

## 反思与复盘

详情页构建了完整的数据聚合链路。正则解析方案简单直接，适合当前的 Markdown 表格格式。子任务和验收标准的解析函数可复用性良好。
